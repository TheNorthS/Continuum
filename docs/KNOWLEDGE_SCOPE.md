# 按知识库范围问答

## 界面使用

1. 打开“知识问答”，点击顶部“问答范围”。新会话默认选中第一个可访问知识库，也可从知识库页点击“向此库提问”。
2. 搜索名称，勾选一个或多个知识库，点击“应用范围”。全选会保存当时的具体库列表，后来新增的库不会自动加入。
3. 输入问题。系统只检索选中库中的文档和图谱片段，不转向网络搜索；资料不足会明确提示。
4. 每条回答显示本次使用的知识库名称，引用可展开查看原文。会话重新打开时恢复已保存的范围。
5. 更换范围后，旧聊天仍可查看，但后续模型上下文从切换处重新开始，避免沿用其他库的回答。范围没有实际变化时保留连续上下文。

知识库页左侧选择当前库，右侧只显示该库的文档与统计。上传、检索试验台、“向此库提问”使用同一个当前库；创建与访问授权收纳在左侧“新建知识库 / 访问授权”中。

未选库、无可访问库、范围权限失效时不能发送问题；正在生成时不能更换范围。权限变化或保存失败会明确报错，不自动放宽范围。

## 接口约定

- `POST /api/v1/conversations`：可传 `{"title":"新对话","base_ids":["库 ID"]}`。
- `GET /api/v1/conversations/{id}`：返回会话元数据，包括 `base_ids` 和 `scope_start_id`。
- `PATCH /api/v1/conversations/{id}/scope`：提交 `{"base_ids":["库一 ID","库二 ID"]}`；保存范围并设置上下文边界。生成期间返回 409。
- `POST /api/v1/conversations/{id}/messages` 和 `/stream`：问题体可带 `base_ids`，在会话租约中校验和保存；省略或 `null` 沿用会话当前范围。
- `POST /api/v1/knowledge/search`：可传 `{"query":"问题","top_k":4,"base_ids":["库 ID"]}`。
- 结果包含 `knowledge_scope`，其 `base_ids`、`base_names` 对应本轮范围。

`base_ids` 传入列表时必须有 1–100 项，重复 ID 自动归并。空列表返回 422，不存在或无读取权限的库返回 404。所有 ID 都经过现行 ACL 校验；客户端不能借选库获得额外权限。

旧版未设置范围的 API 会话和未传范围的独立检索保持“全部可访问资料”的兼容行为。网页始终发送具体库列表；旧会话从网页继续提问时，会将界面显示的列表保存为固定范围。已经设置范围的会话不会因省略参数或传 `null` 回到全部资料。

## 实现与验证

数据库迁移 `0005` 使用新增列保存范围和上下文边界，保留现有会话、消息、文档及授权。开发环境在 `RAGE_AUTO_MIGRATE=true` 时启动自动迁移；生产必须关闭自动迁移并在启动服务前单独执行。流程见[版本升级与索引重建](MIGRATION.md)。

任务局部范围与实时 ACL 在 Repository 层取交集，覆盖本地/Milvus 文档过滤、Neo4j 召回和检索缓存版本。不同并发任务的选择互不覆盖，线程池也继承本轮范围。完成回答前重新校验所选库及每条引用的分块归属。

`backend/tests/test_knowledge_scope.py` 验证单/多库、范围缓存、会话持久化、上下文切换、空列表/无权限拒绝、SSE、并发、最终来源复核、真实 Neo4j 与 Redis L2。前端 `knowledge-scope.test.tsx` 验证选择、搜索、空状态、权限变化、失败回退及知识库页联动。

选库隔离在 `demo` 与 `live` 模式下均生效，不取决于回答模型。模型质量与权限隔离分别验收；公开数据实验见[评测报告](FULL_EVALUATION.md)，当前发布验证见[验证记录](VERIFICATION.md)。
