# 系统架构与运行约束

RAG-E 按 HTTP 接口、业务编排、知识处理和存储适配分层。前端通过统一 API 客户端处理认证、请求签名和 SSE；后端服务由 `Container` 组装，在 FastAPI lifespan 中创建和关闭。

## 组件职责

| 组件 | 职责 |
|---|---|
| API / SecurityService | 认证、请求证明、角色权限、资源授权、限流与审计 |
| ChatService | 会话租约、问答范围、历史上下文、输入与最终输出审查、结果提交 |
| Orchestrator | LangGraph 路由、检索、相关性评分、生成、质量检查及有限重试 |
| KnowledgeService | 文档入库、公共候选池、范围内混合检索、精排与最终片段选择 |
| DocumentProcessor / Embedder | 章节解析、语义分组、长度切分及真实或演示向量 |
| GraphService | 实体关系抽取、证据验证、授权图查询、路径与规则推理 |
| Repository | 业务状态、权限范围、会话和加密数据访问 |
| Cache / Monitoring / Tracing | L1/L2 缓存、指标、分位数、告警和请求追踪 |

SQL 是业务状态的权威来源；本地索引或 Milvus 执行检索。Neo4j、Redis L2 和外部 Langfuse 均按配置启用。共享客户端和检索实例以进程为单位复用，不跨 worker 共享内存。

## 问答编排

![选定知识库的问答流程](assets/diagrams/qa-flow.svg)

- `adaptive`：未固定知识库范围时，根据问题路由到知识检索或配置允许的网络流程。
- `agentic`：未固定范围时使用模型工具调用选择知识检索或网络搜索，日常对话可以选择 direct。
- **已选知识库时**：两种模式均固定检索所选且获授权资料，不调用自由路由，不转向网络或 direct。多轮追问仍可先上下文化。

原始问题与改写后的检索 query 分开保存，生成和回答有效性检查围绕原始问题。来源审查与相关性过滤之后才生成；事实依据通过后才调用有效性检查。

| 检查结果 | 后续行为 |
|---|---|
| 没有可用资料 | 在额度内改写并重新检索，否则返回资料不足 |
| 答案缺少依据 | 在生成额度内用当前资料重新生成 |
| 答案有依据但未解决问题 | 在额度内改写检索；已选库时不转向网络 |
| 相应预算耗尽 | 清空来源并返回资料不足提示 |
| 安全拦截、审查故障、依赖错误或超时 | 独立终止，不进入质量重试，不保存本轮消息 |

默认改写最多 2 次、生成最多 2 次，未固定范围且启用联网时最多搜索一次；问答总预算默认 150 秒。SSE 传输步骤事件与经过最终检查的完整答案，不提前输出候选答案。实际工作流可通过受保护接口 `/api/v1/agents/workflow` 查看。

## 文档处理与索引一致性

支持 UTF-8 Markdown / TXT。先按标题分节，长章节可用相邻句子向量距离做语义分组，最后按长度限制切分。共享模板为最多 1500 字符、组内长度切分重叠 150；不保证章节或语义组之间重叠。代码围栏内的标题符号不会被解析成章节，但长代码块和表格仍可能跨块。

- 内容摘要用于同一知识库中的重复识别；不同知识库可以保存相同资料。
- 先预留文档记录，再写向量索引，最后提交 SQL 分块和 `ready` 状态。部分失败的外部索引数据不直接作为可见资料返回。
- 检索和精排后复核 SQL 就绪状态、所选范围与当前 ACL；缓存命中也受复核约束。
- 删除先标记 `deleting`，阻止继续检索，再清理索引和 SQL。清理失败可重试。
- 图谱状态独立于向量状态，失败可重建；节点和关系保留文档及片段归属。
- 索引配置签名阻止不同 Embedding 空间混用。启用共享参数时，分块规则也纳入签名；变更后的重建方式见[升级与索引重建](MIGRATION.md)。

## 会话与并发

会话采用数据库原子租约防止两轮同时写入。当前上下文使用范围切换之后最近 10 条消息，每条最多 3000 字符；完整历史仍可查看。最终提交前再次检查资源归属，安全拦截、取消、超时或异常不提交本轮消息。资料不足属于独立的最终结果状态，不等同于安全错误。

网络模型、Redis、Neo4j 使用异步客户端；SQL、Milvus、本地模型及主要 CPU 操作通过线程池执行。导入和模型批次均有并发上限；不在模块导入时加载模型、连接数据库或启动交互循环。

## 可观测性与部署边界

请求 ID 关联工作流、检索、模型调用和指标。日志不记录正文或凭据；外部 Langfuse 默认只收集元数据，生产配置禁止正文追踪。

`/api/v1/health/live` 反映进程存活，`/api/v1/health/ready` 检查数据库与向量依赖，不逐次调用付费模型。Prometheus 与内置 Profiler 记录操作时延；存在包含或并行关系的 span 不能简单求和当作总延迟。

当前 IP 限流和 L1 缓存按进程保存，多副本部署需在网关配置全局限流。本地检索适合开发和小语料，较大数据量使用 Milvus。上传仍是请求内索引流程，持久化后台任务队列尚未实现。
