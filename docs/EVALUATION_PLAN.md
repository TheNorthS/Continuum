# 评测方法与指标口径

本项目区分检索质量、回答质量和工程可靠性。配置命令见[评测运行指南](EVALUATION.md)，已完成实验见[最终结果](FULL_EVALUATION.md)。

## 数据集与范围

| 数据集 | 本轮范围 | 主要用途 |
|---|---|---|
| [C-MTEB/T2Retrieval](https://huggingface.co/datasets/C-MTEB/T2Retrieval) | 10,000 文档、1,000 问题，固定采样 | 根据官方相关性标注测召回与排序 |
| [CRUD-RAG](https://github.com/IAAR-Shanghai/CRUD_RAG) | 单 / 双 / 三篇资料 QA 共 2,394 题；45 个所选语料分片 | 测问答文本重合、拒答、拦截、错误和耗时 |

T2 先以 seed 42 抽取问题，纳入这些问题全部标注相关文档，再以 seed 43 抽取干扰资料，严格凑足 10,000 篇。若正例超过指定语料规模则拒绝运行。子集比完整库更容易，不能冒充全量榜单成绩。

CRUD 三个 QA 任务分别为 800 / 797 / 797 题；不包括摘要、续写和幻觉修改任务。官方目录有 48 个文件，已完成基线只使用 45 个 `documents_dup_*` 文件，按非空物理行读取并精确去重为 86,835 条。原排除另 3 个文件的依据不充分，范围更正详见[质量诊断](QUALITY_DIAGNOSIS.md)。

全库评测不将标准答案、思维过程或 QA 附带新闻额外写入索引。小规模 CRUD 子集是从参考新闻构建的受控语料实验，报告必须与全库口径区分。下载版本、文件摘要、采样 ID 与处理规则保存在本地 manifest 中。

## 对照流程

1. 读取与生产相同的 RAG 参数、文档分块和向量模型。
2. 建立隔离 SQL 与 Milvus 索引，核验分块 ID、数量及索引状态。
3. 对同一问题保存混合检索初始候选池；RRF 与 Qwen 使用相同初始候选进行检索对照。
4. Qwen 组通过正式 `KnowledgeService.search` 与 `ChatService` 执行；RRF 组为明确标记的去精排对照。
5. CRUD 执行来源审查、相关性判断、生成、依据与有效性检查及有界重试；T2 只测检索，不生成答案。
6. 汇总逐题指标、错误、拒答、拦截、用量与分阶段耗时。配置变化使用新 run，不混入旧答案。

## 指标与第三方工具

| 层级 | 指标 / 工具 | 解释 |
|---|---|---|
| 检索 | Recall@K、Precision@K、Hit@K、MRR@10、nDCG@10；`ir_measures` | 排名以去重来源文档为单位，使用官方标注 |
| 正常回答题质量 | 归一化 EM、字符 F1、字符 ROUGE-L；`rouge-score` | 仅 status=answered；去引用并规范化文本后计算重合，多参考取最高分 |
| 全量端到端质量 | 同上，保留原始全量分母 | 拒答、错误、拦截记零，与条件质量分别报告 |
| 配对差值 | 2,000 次问题 bootstrap | T2 精排相对 RRF 的差值与 95% 区间 |
| 运行质量 | 回答 / 资料不足 / 拦截 / 错误占比 | 全部计划问题保留在分母 |
| 性能 | p50 / p95 / p99、节点耗时、供应商返回用量 | 含缓存和共享并发上限，不是生产容量压测 |

CRUD 全库没有能直接映射到当前文档 ID 的完整 qrels，因此全库 Recall / MRR / nDCG 为 **N/A**。不能用参考新闻片段哈希伪造全库标注。

**字符 F1 / ROUGE-L 不是语义准确率，模型自身的 supported / useful 也不是真实准确率。** 本轮没有使用 Ragas、LLM 裁判或独立人工全量标注。后续可加入独立人工核验与裁判，但应分别报告。

正常回答题质量按最终 `status=answered` 筛选，资料不足、执行错误、安全拦截不进入该指标分母。分数为入选题得分总和除以正常回答题数，并同时报告“正常回答 / 全部已执行题”的覆盖率。没有正常回答时条件质量为 N/A，不写成零分或满分。生成后被否决属于资料不足，不能重复扣除，也不使用被否决的中间候选答案代替最终结果。

这一口径回答“系统返回答案时，文本质量如何”；全量端到端口径回答“面对全部问题，系统总体交付如何”。两组正常回答题集合可能不同，条件均值差不能直接当作精排的配对提升。统计口径调整不代表模型效果提升，原始逐题记录与全量基线保留。

## 可比性与限制

- 两组固定模型、语料、分块、安全策略和初始候选池；完整问答中的改写会产生后续查询。
- 生成 Top-K 的单位是 chunk，检索报告的单位是来源文档；二者覆盖率不能直接混用。
- 全量端到端分数对失败、拒答与拦截记零；正常回答题分数将其排除并显式给出分母及覆盖率。原始失败记录不删除。
- CRUD 同一事件的不同任务相关，当前不把全部 QA 当作独立样本计算回答置信区间。
- 评测使用独立 SQLite，生产模板为 PostgreSQL；参数对齐不等于验证了生产 SQL 与公网入口性能。
- 外部 API、服务版本及输入语料会影响结果；模型与端点变更需重新建索引、评测并记录指纹。
- 质量优化应按事件 ID 划分调参与留出验证，避免反复在已见测试题上调参后仍声称未见测试成绩。

早期 1000/150 固定分块和小样本方案保留在[历史归档](archive/README.md)，不作为当前运行指引。
